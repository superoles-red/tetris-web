# Тетрис (Tengen, NES) в браузере — без эмулятора

**Играть:** https://superoles-red.github.io/tetris-web/

Порт запускает **оригинальный Tetris для NES** (Tengen, 1988), который вы
приносите сами: один файл `.nes`. Код игры из вашего ROM статически
перекомпилируется в WebAssembly прямо на устройстве. Эмулятора NES в проекте
нет — работает наш перекомпилятор 6502 → WASM, наша модель PPU/APU и
оригинальные данные вашего картриджа.

- Мы не поставляем и не храним игру: ни ROM, ни графику, ни музыку.
- Файл никуда не отправляется: компиляция и игра идут локально в браузере.
- Вся картинка и звук — ровно те, что в вашем ROM: PPU/APU читают его данные.
- Установка на главный экран, офлайн-запуск, сохранения и рекорды
  (для известных дампов), кнопка «другой ROM» в любой момент.
- Интерфейс оболочки — наш, на русском и английском.

## Какой файл нужен

Один файл — дамп картриджа **Tengen Tetris** для NES, `.nes`, около 48 КБ.
Поддерживаются известные дампы (см. `data/dumps.json`) и другие NES-ROM с
небанкованными мапперами (0, 3, 148) в совместимом режиме.

| Дамп | SHA-256 | Режим |
|---|---|---|
| `Tetris (USA) (Tengen) (Unl)` | `53970a2b…ab8ea62` | полный |
| `Tetris (U) (Unl) [T+Rus1.11 PSCD (10.11.2015)]` | `33f04ac3…11d46` | полный (русский) |

В репозитории нет ни ROM, ни дампов CHR/PRG, ни скриншотов игры, ни записей
музыки — только наш код и таблица известных дампов с хешами.

## Требования

- Браузер с WebAssembly и ES-модулями: Chrome/Edge 90+, Safari 15+,
  Firefox 90+ (мобильные версии тоже). Нужен IndexedDB — он есть везде.
- Установка PWA — по желанию; после первого запуска ROM хранится в браузере.

## Как это устроено

```
index.html, app.js           оболочка: карточка → ROM → паспорт → установка → игра
compositor.js, controls.js   раскладка оригинального кадра и тач-управление
src/nes/rom.js               разбор iNES, профиль дампа, хэши
src/nes/compile.js           статическая трансляция 6502 → WebAssembly
src/nes/wasm.js              минимальный энкодер бинарного WASM
src/nes/console.js           шина, тактирование, прерывания, снапшоты
src/nes/ppu.js               PPU: регистры, скролл, спрайты, кадровый рендер
src/nes/apu.js               APU: 2 импульса, треугольник, шум, огибающие
src/nes/engine.js            браузерный движок: rAF, звук, пауза, снапшоты
src/byop/                    IndexedDB: ROM, кэш WASM, обложка, меню-чекпоинт
```

Подробности, контракты модулей и правила — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Коротко о перекомпиляции: для каждого адреса ПЗУ `$8000…$FFFF` генерируется
WASM-функция, исполняющая одну инструкцию 6502 и возвращающая
`nextPC | (cycles << 16)`. JS-консоль вызывает их по одной, тактируя PPU/APU и
обрабатывая прерывания на границах инструкций. В рантайме нет fetch/decode —
каждая инструкция уже нативный WASM-код. Скомпилированный модуль кэшируется в
IndexedDB по SHA-256 ROM.

## Разработка

```bash
npm install                # jsnes нужен только для сравнения с эталоном (dev)
npm run serve              # локальная статика, http://localhost:8080
npm test                   # тесты без игровых ROM (CPU conformance тянется по пину SHA)
node tools/build-site.mjs --output /tmp/site   # сборка статического сайта
node tools/compare.mjs --rom /path/to/game.nes  # dev: сравнение с JSNES-эталоном
```

Игровые ROM в репозиторий не коммитятся и в сборку сайта не попадают
(`tools/build-site.mjs` проверяет артефакт). Для локальных проверок используйте
свои файлы и свой путь.

## Процесс разработки (spec-kit)

Дефекты и фичи ведутся через [Spec Kit](https://github.com/github/spec-kit):
`specs/<номер>/spec.md` (сценарии и критерии приёмки) → `plan.md` → `tasks.md`.
Задача считается выполненной только когда её критерий проверен.

Перед сдачей обязательно прогнать самопроверку (нужен установленный `playwright-core`
и Chrome/Chromium; ROM не входит в репозиторий):

```bash
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright-core/index.mjs \
  ROM_PATH=/path/to/game.nes node tools/self-play.mjs
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright-core/index.mjs \
  ROM_PATH=/path/to/game.nes node tools/ui-audit.mjs
```

`self-play-test.mjs` проходит партию до game over, вводит имя и проверяет таблицу
рекордов. `ui-audit.mjs` снимает метрики/скриншоты по титульной рамке, салютам,
орнаменту меню, рекордам и Continue. Результаты аудита — `/tmp/audit-report.json`.
